# Matiane / მატიანე

Студия фотокниг с внутренними страницами 19 × 24 см и внешней обложкой 19,5 × 24,5 см на английском, грузинском и русском.
Рабочий сервис: https://matiane.57.129.177.67.sslip.io.

## Работа с книгами

В кабинете создайте книгу на **40, 60 или 80 внутренних страниц**. Передняя и
задняя обложки добавляются отдельно и имеют подписи. В редакторе и превью
показаны развороты: первая внутренняя страница справа, затем пары 2–3, 4–5 и
так далее. Пустые внутренние стороны обложек помогают показать расположение
страниц; в PDF они не добавляются. Отдельный редактор обложки показывает заднюю часть слева, корешок и переднюю часть справа. Ширина корешка (начальная 8 мм) и загиб каждой кромки задаются по шаблону типографии; текст корешка редактируется отдельно. Новые книги имеют формат 190 × 240 мм внутри и 195 × 245 мм снаружи. Старые книги остаются A5; изменить формат можно в правой колонке, сохранив кадрирование.

Загружайте JPG, PNG, WebP, HEIC/HEIF (до 30 MB на файл, 200 фото на книгу).
Выберите рамку и нажмите на фотографию в библиотеке или перетащите её.
Кадрируйте фото прямо в рамке: перемещение мышью или пальцем, масштаб колесом,
двумя пальцами или кнопками +/−. Фото всегда заполняет рамку и обрезается по
её границам: уменьшение ниже заполнения и сдвиг с пустыми полями невозможны.
«Заполнить рамку» возвращает минимальный масштаб и центр. Кадрирование
хранится отдельно для каждой рамки. Стрелки и +/− работают с клавиатуры.
Использованные фото помечаются в библиотеке, есть фильтр неиспользованных.
Предупреждение на фото показывает фактический DPI с учётом масштаба:
ниже 150 — красное, 150–299 — жёлтое; рекомендуемый минимум 300 DPI.

Нажмите на текст или пустое текстовое поле на листе: поле ввода в правой
колонке получит фокус. Изменения сразу видны на макете. Здесь же доступны
выбор шрифта, размер, цвет, выравнивание, жирное начертание, курсив и
подчёркивание. Плавающее окно редактирования текста убрано.
Внутренние страницы переставляются в нижней линейке перетаскиванием,
стрелками или вводом номера. Обложки закреплены. При уменьшении числа страниц
сначала сохраняется отдельная резервная копия всей книги. Undo/Redo хранит
30 действий в текущем сеансе. «Удалить страницу» удаляет выбранный внутренний
лист, сдвигает следующие и добавляет пустой в конец. Объём 40/60/80 сохраняется;
обложки удалить нельзя. Фотографии остаются в библиотеке. Удаление отменяется
через Undo и попадает в историю версий у вошедшего пользователя.

Для английского и русского: Montserrat, Manrope, Matiane Book Serif (Lora),
Cormorant Garamond, Matiane Display (Playfair Display), PT Serif, Alegreya,
Caveat, Marck Script, Bad Script. Названия производных Lora и Playfair изменены
по правилам OFL; исходные авторы указаны в лицензиях.
Для грузинского отдельный независимый список: BPG Ingiri, Algeti, Glaho,
Chveulebrivi, Elite, Nino Medium, Nino Medium Condensed, Courier, Serif,
Serif Modern. Все бесплатны и допускают коммерческое использование.
Оригинальные курсивные начертания подключены там, где они существуют;
для остальных курсив и жирное начертание синтезируются. Мтаврули при
необходимости использует Noto Georgian. Старые проекты сохраняют свои
исходные шрифты. Лицензии, источники и правила статических производных:
[public/fonts/SOURCES.md](public/fonts/SOURCES.md).

## Кабинет и сохранение

Администраторы задаются серверной переменной `MATIANE_ADMIN_EMAILS` (список
email через запятую). Роль проверяется сервером в каждой сессии; клиент не
может назначить её себе. В разделе «Все книги» видны все серверные книги,
включая будущие, с владельцем. Просмотр не меняет чужую книгу и не запускает
автосохранение. Копирование создаёт свою книгу с новыми ID, сохраняет оригинал
и его историю; фотографии остаются приватными с отдельными правами владельцев.
Администратор может выгрузить PDF и проект при просмотре. Обычные аккаунты
сохраняют доступ только к своим книгам. Локальные браузерные черновики не
видны серверу до входа: при регистрации, входе и открытии сайта с действующей
сессией все гостевые книги этого браузера автоматически сохраняются в аккаунте,
после чего становятся видны администратору. Переносятся также закрытые книги.
Индикатор показывает ход загрузки. При сбое исходный черновик остаётся на
устройстве, есть «Повторить загрузку»; повторное сохранение не создаёт дубль
и не перезаписывает более новую серверную версию.

Без входа доступны несколько черновиков на этом устройстве (IndexedDB).
Для сохранения между устройствами войдите по email и паролю. Фотографии,
книги и версии аккаунта приватны: доступ проверяется сервером. Автосохранение
срабатывает после паузы в редактировании. История сохраняет последние 30
автоматических версий и до 50 именованных версий на книгу. Восстановление
создаёт новую версию, сохраняя предыдущую историю. При изменениях на другом
устройстве сохранение остановится с выбором последней версии или отдельной
копии; чужие изменения не перезаписываются. Лимиты аккаунта: 20 книг и 1 GB
фотографий, включая фотографии в сохраняемых версиях.

При регистрации скачайте и сохраните код восстановления. Если пароль забыт,
код позволит назначить новый пароль и получить новый код; старый код и все
старые сессии перестанут работать. SMTP и восстановление по письму пока не
подключены. Локальные копии аккаунтов показываются после входа в соответствующий
аккаунт. Ошибки сети оставляют черновик на устройстве. Для независимой копии
используйте «Скачать проект»: JSON включает фотографии и весь макет.

Старый http://57.129.177.67 остаётся доступен для локальных проектов. Старые
книги автоматически мигрируют без потери исходных внутренних страниц; запись
первой версии остаётся в IndexedDB. Нажмите «Перенести книгу в защищённую
студию», чтобы передать её в HTTPS-версию. «Открыть защищённую студию» переносит
все гостевые книги со старого адреса и открывает вход в аккаунт; исходные
книги на старом адресе остаются резервными копиями. Используйте тот же браузер
и устройство, где сохранён проект: разные адреса имеют отдельные локальные
хранилища. При запрете всплывающего окна или
сбое передачи скачайте проект и откройте его в защищённой студии.

## Печатный PDF

Экспорт включает все листы, только внутренние листы или только обложки.
Есть два независимых формата:

- **Постраничный** (основной для большинства типографий): внутренние страницы
  190 × 240 мм; с вылетами 3 мм — 196 × 246 мм, TrimBox 190 × 240 мм.
- **Развороты в порядке чтения**: пары 2–3, 4–5… размером 380 × 240 мм;
  с внешними вылетами — 386 × 246 мм. Первый и последний внутренние листы
  экспортируются отдельно; виртуальные внутренние стороны обложки не добавляются.

В обоих режимах обложка — единый разворот задняя / корешок / передняя.
Ширина до вылетов: 2 × ширина внешней обложки + корешок + 2 × загиб.
Высота: высота внешней обложки + 2 × загиб. При стандартном корешке 8 мм
и загибе 0 новая обложка имеет размер 398 × 245 мм, с вылетами 404 × 251 мм.
40 внутренних страниц с обложкой дают 41 PDF-страницу в постраничном режиме
или 22 в режиме разворотов. Для передачи в типографию обычно скачиваются
отдельно внутренний блок и разворот обложки. Для старых A5 книг PDF использует
их сохранённые размеры.

Фон и полноформатные фотографии продолжаются во внешние вылеты. RGB,
встроенные шрифты со всеми использованными символами; текст остаётся текстом.
В PDF нет подсказок редактора и предупреждений о качестве. Печатать в 100%.

В окне экспорта можно выбрать качество изображений для обоих форматов:

- **Исходное качество** (по умолчанию): все пиксели фотографий из сохранённой
  книги сохраняются; JPEG встраивается без повторного сжатия. Это может давать
  большой PDF, поскольку включает исходное разрешение и части фото, скрытые
  кадрированием. Одинаковые источники фото встраиваются один раз, даже если
  загружены под разными именами; встраиваются только использованные шрифты.
- **Для печати 300 DPI**: разрешение рассчитывается по самому крупному
  использованию каждой фотографии в выбранных листах с учётом приближения и
  вылетов. Скрытые части кадра удаляются; при нескольких кадрированиях
  сохраняется их общая область. JPEG сохраняется с качеством 95%; PNG остаётся
  PNG. Низкое разрешение не увеличивается, предупреждения о качестве остаются.
  Если обработанный файл не меньше исходного, встраивается исходный.

300 DPI — стандартное разрешение для обычной фотопечати, но уменьшение числа
пикселей и повторное JPEG-сжатие не являются сжатием без потерь. Для требований
типографии выше 300 DPI выберите исходный режим. Размер PDF зависит от числа
уникальных фотографий, их разрешения, содержания и кадрирования. Фото, макет и
версии в кабинете не меняются при экспорте. Постраничный PDF и PDF разворотов
создаются отдельно; скачивание одного не включает второй.

Постраничный файл оставляет типографии спуск полос под её оборудование,
бумагу и переплёт. Развороты выбираются, когда типография просит именно
соседние страницы в порядке чтения; это не спуск полос для печатного листа.
Например, [Lulu Book Creation Guide](https://assets.lulu.com/media/guides/en/lulu-book-creation-guide.pdf)
и [Blurb](https://support.blurb.com/hc/en-us/articles/207792946-PDF-to-Book-specifications-and-checklist)
требуют отдельные страницы внутри и отдельный полный файл обложки;
[Saal Digital](https://www.saal-digital.com/service/professional-zone/create-your-files-in-indesign/)
принимает внутренний блок разворотами. Универсального требования нет.
Точный корешок зависит от бумаги и переплёта; 8 мм не является расчётом
для конкретной типографии. Загибы и вылеты задаются по её шаблону.
PDF/X, CMYK и метки реза автоматически не создаются.

## Локальная разработка

Node.js **24 LTS**, npm. Проверено на Node 24.19.0. В корне проекта:

```sh
npm ci
npm run dev -- --port 5173
```

Редактор доступен по адресу Vite. Для аккаунтов запустите второй терминал:

```sh
SECURE_COOKIES=false PUBLIC_ORIGIN=http://127.0.0.1:5173 npm run dev:server
```

В Windows PowerShell:

```powershell
$env:SECURE_COOKIES="false"
$env:PUBLIC_ORIGIN="http://127.0.0.1:5173"
npm run dev:server
```

Откройте именно http://127.0.0.1:5173. Vite проксирует `/api` на порт 3000.
Данные разработки находятся в игнорируемой папке `.matiane-data`.
`npm run build` создаёт статические файлы в `dist/`. Для production аккаунтам
также нужны Node-сервер, постоянное хранилище и HTTPS-прокси.

## VPS и автообновление

Конфигурация действующего сервера: [deploy/COOLIFY.md](deploy/COOLIFY.md).
Статический сайт и сервер аккаунтов — отдельные приложения Coolify. Изменения
в `main` автоматически публикуются проверяющим GitHub процессом. Данные
SQLite и фотографии находятся в постоянном Docker volume сервера аккаунтов
и сохраняются при пересборке контейнеров. HTTPS-шлюз Nginx управляется
`deploy/setup-matiane-gateway.sh`, сертификат продлевает certbot.timer.

Сервер создаёт согласованную SQLite-копию раз в день и хранит её 14 дней в
`/data/backups`. Неиспользуемые файлы фото удаляются не раньше 30 дней, что
позволяет использовать эти копии. Они находятся **на том же VPS**: для
восстановления при потере сервера нужно отдельно копировать весь volume,
включая `/data/photos`, во внешнее хранилище. Удаление Docker volume удаляет
данные аккаунтов. Не запускайте старый systemd-таймер публикации одновременно
с Coolify и не включайте Traefik, пока host Nginx занимает порты 80/443.

## Проверки

```sh
npm test
npm run test:e2e
npm run build
```

Vitest проверяет модель и перенос старых проектов; Node test — авторизацию,
приватность, CSRF, версии, конфликты, квоты, сохранность после рестарта и
SQLite backup. Playwright проверяет кабинет, фиксированные страницы,
обложки, развороты, кадрирование, перестановку, текст, PDF, аккаунты и мобильную
ширину. Используется `/usr/bin/chromium`; при другом расположении измените
`playwright.config.js`. Vite и тестовый backend запускаются автоматически.
Для реального HEIC-теста задайте `MATIANE_HEIC_FIXTURE` с путём к HEIC-файлу.
Использован публичный `strukturag/libheif/examples/example.heic`, без включения
изображения в этот репозиторий. `MATIANE_TEST_URL` позволяет проверить готовый
сайт. HTTP-сайт проверяется без аккаунтов, HTTPS — с тестовым аккаунтом и
удалением созданной книги.
